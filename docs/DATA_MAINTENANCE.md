# 데이터 운영 절차

카탈로그: `src/data/catalog.js`. 현재 6개 모델/2개 제조사, 2026-11-13 확인. 가격/재고 API, 크롤링 예약 작업, 자동 갱신 기능 없음.

## 정기 검토
권장: 매월 링크 확인과 변경 확인. 사양 근거 유효기간은 90일이며 다음 검토 기한은 2027-02-11 KST다. 그 이후(2027-02-12부터) 재확인하지 않은 후보는 추천에서 제외된다. 이는 서비스의 보수적 정책이다.

1. `npm run data:audit`로 출처 누락·날짜·타입을 검사한다. 미래 기준 확인은 `node scripts/audit-data.js --date=2027-02-12`처럼 실행한다. 날짜 인자는 점검용이며 앱의 날짜를 바꾸지 않는다.
2. `npm run data:links`로 최대 3개 동시 요청, 요청당 15초 제한으로 공식 URL의 접근을 검사한다. 403/429/타임아웃은 미확인으로 취급하고 우회하지 않는다. **200은 사양 확인 성공이 아니다.**
3. 원문에서 모델명, SKU/옵션, 지역을 먼저 확인한다. 브랜드 페이지가 신제품으로 리다이렉트하면 같은 모델로 간주하지 않는다.
4. 추천에 쓰는 필드를 원문과 대조한다. UI에서 사양이 접혀 있으면 동일 페이지의 구조화 데이터도 참고할 수 있으나, 다른 모델의 데이터가 섞이지 않았는지 확인한다.
5. 사실을 재검토한 출처만 `checkedAt`을 갱신한다. 해당 날짜에 확인하지 않은 다른 필드를 같은 출처로 묶어 일괄 최신 처리하지 않는다. 필요하면 출처 기록을 분리한다.
6. 충돌/누락/지역 차이는 null과 구체적 메모로 남긴다. 대체 SKU를 기존 ID로 덮어쓰지 않는다. 소음 마케팅은 실측으로 승격하지 않는다.
7. `npm test`, `npm run check`, `npm run build`, `npm run test:e2e`를 실행하고 변경 근거를 기록 후 커밋한다.

## 필드 형식
`{ value, source, note }`. `source`는 해당 제품의 sources[].id다. 알려진 값은 확인 메모와 공식 출처가 필수다. 모르는 값은 `value: null, source: null`이며 불명 이유를 note에 적는다.

연결 배열은 제조사의 입력 연결 지원 목록이다. USB 충전 여부만으로 wired를 넣지 않는다. OS 배열은 명시적으로 검증한 기본 입력 OS만 열거한다. 목록 밖의 OS는 비호환 확정이 아니라 미확인으로 처리한다. 기기 전환은 동시에 여러 기기에 타이핑한다는 의미가 아니다.

무게는 제조사마다 배터리 포함 기준이 달라 정렬에 사용하지 않는다. 수신기 지원과 구성품 포함은 별도 필드다. 도식은 실제 키 수/키 위치/모델 이미지가 아니며 사진으로 재사용하면 안 된다.

## 현재 알려진 미확인/충돌
- K650 건전지 AA/AAA 충돌. ‘교체형 건전지’만 채택.
- B1/B6/V1의 수신기 포함 여부는 이번 텍스트 확인으로 확정하지 않음.
- Keychron 글로벌 ANSI 모델의 한국어 각인·국내 판매·보증·배송 총액 미확인.
- Keychron iPadOS 지원은 이번 문구로 확정하지 않음. iOS에서 추론하지 않음.
- MX Keys S, B1/B6의 구체적 스위치 구조는 이번 범위에서 미확인. 키 높이는 별도 사양.
- 국내 총 가격과 동일 조건 실측 소음은 전 제품 미확인.

가격/소음에 숫자를 채우는 것만으로 엄격한 조건이 활성화되지는 않는다. 향후 가격에는 판매처·통화·세금·배송비·시각·지역·재고, 소음에는 측정 장비·거리·공간·타건 조건이 추가로 필요하다. 해당 기능은 별도 기획과 검증 후 확장한다.
